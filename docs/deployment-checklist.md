# قائمة التحقق قبل النشر — AL Reem

هذه القائمة لا تنفّذ نشرًا ولا تنشئ موارد مدفوعة. استخدمها قبل تغيير إعدادات Cloudflare أو دمج أي فرع.

## 1. التحقق من مصدر النشر

- [ ] افتح إعدادات Worker `al-reem` ثم إعدادات Builds / Deployments.
- [ ] تحقق من مستودع GitHub المرتبط والفرع المحدد للنشر.
- [ ] تحقق من أن الفرع المحدد يحتوي `index.html` و`styles.css` و`app.js` في جذر المستودع.
- [ ] لا تغيّر فرع الإنتاج إلى `phase-1-foundation` ولا تدمجه إلى `main` قبل مراجعة التغييرات والموافقة.
- [ ] إذا كان المصدر هو `main`، افحص محتوياته الحالية؛ وجود README وحده لا يكفي لبناء الموقع.

## 2. إعدادات البناء

المشروع الحالي واجهة ثابتة بملفات HTML وCSS وJavaScript، ولا يحتاج إلى خطوة bundling.

- Build command: اتركه فارغًا ما لم يُضف نظام بناء لاحقًا.
- Root directory: جذر المشروع الذي يحتوي `index.html`.
- Deploy command: لا تشغّله قبل التأكد من وجود ملف إعداد Wrangler صالح مثل `wrangler.toml` أو `wrangler.jsonc`، ومن أن إعدادات النشر تشير إلى المجلد الصحيح.
- تحقق من اسم Worker ووجود إعداد `assets` إذا كان النشر سيستخدم Cloudflare Workers Static Assets. لا تنشئ Worker جديدًا لمجرد تجاوز الخطأ.

## 3. الاختبارات

من جذر المستودع، عند توفر Node.js:

```bash
node tests/smoke-test.mjs
```

هذا اختبار ساكن فقط. بعد نجاحه:
- [ ] افتح الصفحة على هاتف وحاسوب.
- [ ] اختبر تبديل العربية والإنجليزية واتجاه RTL/LTR.
- [ ] اختبر تواريخ المغادرة والعودة والحقول المطلوبة.
- [ ] تأكد من وضوح أن النموذج معاينة محلية ولا يرسل حجزًا فعليًا.

## 4. قاعدة البيانات

- [ ] راجع ملف الترحيل SQL قبل تشغيله.
- [ ] طبّقه على مشروع Supabase تطويري منفصل فقط.
- [ ] اختبر سياسات RLS بحساب زائر ومستخدم عادي ومسؤول.
- [ ] لا تستخدم بيانات ركاب حقيقية في الاختبارات.
- [ ] لا تخزن مفاتيح الخدمة أو كلمات المرور في ملفات الواجهة أو المستودع.

## 5. شروط السماح بالإطلاق

لا يُعد الموقع جاهزًا لحجوزات حقيقية إلا بعد:
- نجاح البناء والنشر ومعاينة الموقع.
- اختبار قاعدة البيانات والصلاحيات.
- وجود تدفق فعلي لحفظ طلب الحجز ومراجعته يدويًا.
- تحديد قناة تواصل رسمية وسياسة خصوصية مناسبة.
- توضيح أن إرسال الطلب لا يعني تأكيد التذكرة.
