# AL Reem — منصة السفر وحجز الطيران

منصة ويب عربية وإنجليزية قيد التطوير، بهوية مستقلة تعتمد على الأحمر الملكي والعنابي والأبيض. المرحلة الحالية هي نموذج تأسيسي للواجهة فقط.

## الحالة الحالية

- [x] هيكل واجهة أولي بدون اعتماديات برمجية خارجية.
- [x] واجهة عربية افتراضية مع دعم الإنجليزية.
- [x] دعم اتجاهي RTL وLTR.
- [x] نموذج بحث عن رحلة مع تحقق أساسي من المدخلات.
- [x] معاينة محلية لملخص البحث.
- [x] أقسام وجهات توضيحية مع تنبيه بأنها ليست عروضًا حقيقية.
- [ ] إضافة ملف شعار الغزال الأصلي إلى أصول المشروع.
- [ ] مراجعة التصميم على متصفحات وأحجام أجهزة مختلفة.
- [x] إعداد مسودة أولية لمخطط قاعدة البيانات وترحيل SQL للمراجعة (لم تُطبّق ولم تُختبر على Supabase).
- [ ] إعداد المصادقة والصلاحيات ولوحة الإدارة.
- [ ] تنفيذ طلبات الحجز اليدوي وربطها بقاعدة البيانات.
- [ ] إضافة الاختبارات الآلية.

**تنبيه:** لا يوجد اتصال بمزود طيران أو قاعدة بيانات أو بوابة دفع في هذه المرحلة. نموذج البحث لا يرسل أي طلب ولا ينشئ حجزًا فعليًا.

## التشغيل المحلي

لا يحتاج النموذج الحالي إلى تثبيت حزم.

1. استنسخ المستودع:
   `git clone https://github.com/hameeddakhil3-coder/al-reem.git`
2. انتقل إلى مجلد المشروع:
   `cd al-reem`
3. شغّل خادم ملفات محليًا، مثل:
   `python -m http.server 8000`
4. افتح `http://localhost:8000` في المتصفح.

يمكن فتح `index.html` مباشرةً في بعض المتصفحات، لكن يفضّل استخدام خادم محلي لاختبار سلوك الصفحة بصورة أقرب إلى بيئة التشغيل المعتادة.

## الملفات

- `index.html`: هيكل الصفحة الرئيسية ونموذج البحث وأقسام المحتوى.
- `styles.css`: متغيرات الهوية البصرية والتصميم المتجاوب وحالات التركيز وإمكانية الوصول.
- `app.js`: الترجمة، وتبديل اللغة، والتحقق من نموذج البحث، ومعاينة الملخص محليًا.

## الهوية والشعار

الألوان المعتمدة:
- الأحمر الملكي: `#850D24`
- العنابي الداكن: `#480815`
- الأبيض: `#FFFFFF`
- الرمادي الفاتح: `#F4F1F0`

يستخدم النموذج الحالي علامة نصية مؤقتة **AR**، وليست الشعار الرسمي. يجب إضافة صورة الغزال الأصلية التي قدمها صاحب المشروع كملف أصول، ثم تحديث موضع العلامة لاستخدامها دون إعادة رسمها أو استبدالها. لا تعتبر الهوية مكتملة قبل هذه الخطوة.

## قاعدة البيانات — مسودة محلية فقط

يفضّل تقييم PostgreSQL عبر Supabase للبيانات والمصادقة والتخزين بعد مراجعة الخطة والتكلفة. الجداول الأولية المقترحة:

- `profiles`: بيانات الملف الشخصي المرتبطة بمستخدم المصادقة.
- `roles` و`role_permissions`: الأدوار والصلاحيات.
- `bookings`: طلبات الحجز.
- `booking_travelers`: المسافرون المرتبطون بالطلبات.
- `booking_flights`: تفاصيل الرحلات المرتبطة بالطلب.
- `booking_status_history`: تاريخ تغييرات الحالة.
- `destinations` و`banners` و`homepage_sections`: المحتوى المرئي.
- `static_pages` و`faq_items` و`site_settings`: محتوى الموقع وإعداداته.
- `contact_messages`: رسائل التواصل.
- `audit_logs`: سجل العمليات الإدارية المهمة.

أُضيفت مسودة ترحيل SQL في `supabase/migrations/202610190001_initial_schema.sql` مع جداول أولية وتعليقات عربية وسياسات RLS، والتحقق من انتقالات حالة الحجز تلقائيًا، وتسجيل تاريخ الحالة، ومنع انتحال هوية صاحب رسالة التواصل. هذه المسودة لم تُطبّق ولم تُختبر على قاعدة بيانات؛ لا توجد موارد Supabase منشأة. يجب إجراء مراجعة أمنية واختبار عملي للسياسات والقيود قبل اعتمادها أو تخزين بيانات حقيقية.

## الأمان والتكلفة

- لا توجد مفاتيح API أو أسرار في ملفات المشروع.
- لا توجد موارد مدفوعة أُنشئت كجزء من هذا التغيير.
- لا توجد عملية نشر إلى الإنتاج.
- لا تُستخدم بيانات الوجهات التوضيحية كبيانات رحلات أو أسعار حقيقية.

## الاختبارات

تمت مراجعة الملفات المضافة منطقيًا، لكن لم يُشغّل متصفح أو خادم اختبار ضمن هذا التغيير. يلزم اختبار العرض والتفاعل فعليًا في بيئة التطوير قبل اعتبار المرحلة مقبولة.

## الخطوات التالية

1. إضافة الشعار الأصلي إلى أصول المشروع وربطه بالواجهة.
2. مراجعة التصميم في الهاتف والحاسوب.
3. مراجعة مسودة SQL أمنيًا وتشغيليًا ثم اختبارها في بيئة تطوير منفصلة.
4. مراجعة خطة Supabase والتكلفة قبل إنشاء أي مورد.
5. تنفيذ المصادقة ولوحة الإدارة وطلبات الحجز اليدوي على مراحل.


## اختبارات التحقق الساكنة

أضيف ملف `tests/smoke-test.mjs` لتشغيل فحوصات أولية باستخدام Node.js دون تثبيت حزم إضافية.

من مجلد المشروع، شغّل:

```bash
node tests/smoke-test.mjs
```

يتحقق الاختبار من وجود عناصر أساسية في الصفحة، وربط ملفات CSS وJavaScript، ورسالة منع تاريخ المغادرة السابق، وبعض ضوابط مسودة SQL.

**حدود الاختبار:** هذه فحوصات نصية ساكنة فقط؛ لا تفتح متصفحًا، ولا تختبر التفاعل الحقيقي، ولا تنفذ SQL أو تتحقق عمليًا من سياسات RLS. يجب تشغيلها محليًا وتسجيل النتيجة الفعلية قبل اعتبارها ناجحة.
